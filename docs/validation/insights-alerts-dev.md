# Dev API before/after validation — PR #329

Date: 2026-10-06. Baseline: `15b6b1c` (pre-change merge base). Feature: `fix/audit-insights-alerts`, including the empty-budget-response fix. Both revisions were archived, dependency-installed, and built in separate temporary directories. The built stdio servers received equivalent MCP `tools/call` inputs against `https://api-dev.doit.com`. Authentication came from the repository's credential helper and remained in process environments. No customer values or credentials are recorded here.

The baseline and feature both returned validation errors for an ID-only alert patch and for an invalid insight status. Those checks establish compatibility and regression coverage; they do not reproduce a baseline failure. The Google Cloud incident page and ordinary alert listing also behaved the same in both builds. A resource page without a next cursor and the sparse category-page behavior remain covered by deterministic tests, because the selected live pages did not expose those exact edge cases. Demo-token filtering is fixture-only by design and was not counted as dev API validation. Live alert enum variants, budget writes, hosted OAuth, and switched-customer behavior were not exercised.

Cleanup ran in `finally`: one alert and three disposable insights were deleted through their documented API routes. Independent GET requests returned 404 for every created resource. Their resource results were removed with the parent insights. No resources remain; no IDs need follow-up. No deploy, package publication, merge, notification workflow, or unrelated branch change was performed.
